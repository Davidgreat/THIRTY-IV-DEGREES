# Checkout hotfix validation

Local environment: PHP 8.4, MariaDB 11.8 and Chromium/Playwright, using synthetic accounts/orders and a local TLS Paystack mock with a trusted test certificate. No real card, live key or real charge was used.

- **29 checkout browser checks passed** (`tests/checkout-payment.js`): actual mobile delivery, pickup and gift submissions; desktop submission; direct hosted-gateway navigation; missing-field feedback; server recipient-phone validation; retained recipient/contact details; invalid schedule disclosure/error/retention; successful payment handoff after clearing the schedule; duplicate-submission recovery; no false paid status; controlled gateway activation rejection remaining on the saved order with retry; no key disclosure; zero browser JS errors.
- **34 existing payment/account regression checks passed** (`tests/payments.php`), including encryption, mode checking, verification, pending checkout reuse, idempotency, inventory accounting, booking state, webhook authentication and password recovery.
- **17 updater checks passed** (`tests/update-611.php`): the exact hotfix archive was installed through a clean 6.1.0 fixture's existing uploader; version 6.1.1 recorded; Paystack credentials/activation/mode, config.php, uploaded media, orders and bookings preserved; code-only restore point created; duplicate version rejected; new helper/assets installed. Verification, refund and integration-encryption file hashes remained unchanged.
- **22 existing HTTP workflow checks passed** (`tests/functional.py`) with payments paused, covering settings, CSRF, banners, guest order access, booking validation, account records, manager/customer restrictions and unsigned webhook rejection.
- PHP syntax and new JavaScript syntax passed. The update ZIP contains only six changed runtime files plus its update.json manifest. No database migrations, hosting configuration or customer uploads are included.

The originally reported production loop was not reproduced exactly: valid submissions in the 6.1.0 local copy reached the order-review page. The new handoff and error-handling behaviors were verified against the mock gateway. These results do not prove actual live Paystack account authorization or hosted Apache/CDN/session behavior. If the hosting still prevents a request, the visible error and sanitized HTTP audit status are the next diagnostic evidence.
